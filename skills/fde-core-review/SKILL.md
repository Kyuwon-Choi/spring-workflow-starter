# 핵심 기능의 선택과 근거 정리

사용자가 지정한 핵심 기능을 실제 코드·요구·실행 근거와 연결해 설명한다. 지정하지 않았다면 과제의 핵심 결과를 만드는 기능부터 고르고 선택 근거를 밝힌다. 로그인 같은 주변 기능까지 일괄 분석하지 않는다. 목적은 그럴듯한 사후 설명을 만드는 것이 아니라 사용자가 구현과 한계를 자기 말로 설명할 수 있게 하는 것이다.

## 근거부터 확인

- 해당 요구와 실제 담당자 답, 핵심 진입점→계산/판정→저장/출력 코드, 관련 테스트·실행 결과만 읽는다. 기존 WORK/결정 기록이 있으면 재사용한다.
- `요구로 확인됨 / 코드에서 확인됨 / 실행으로 확인됨 / 추정·미확인`을 구분한다. 주석·README·테스트 이름만으로 구현이나 통과를 확정하지 않는다. 실행 근거는 확인한 코드 버전과 연결하며 이후 변경의 영향을 밝힌다.
- 코드나 기록이 없으면 제공된 설명 범위만 정리하고 미확인 항목을 남긴다. 알고리즘 이름·계산식·실측값·담당자 합의를 추측해 채우지 않는다. 설계 단계라면 계획으로 표시하고 구현/검증 완료로 쓰지 않는다.

## 다섯 질문으로 정리

1. **무엇을 결정하는가?** 실제 입력·출력·단위·결정 변수를 적고 핵심 파일/함수로 연결한다. 개별 항목의 판정인지 여러 대상/공유 자원을 함께 결정하는지 구분한다. 이름이 없는 방법은 실제 처리 단계로 설명한다.
2. **반드시 지킬 조건과 줄일 목표는 무엇인가?** 필수 조건의 출처·서버 검사 위치·위반 시 처리를 확인한다. 선호/비용과 필수 조건을 섞지 않는다. 목적식이 있으면 항·단위·가중치 근거를 밝힌다. 최적화가 아닌 규칙 기반 기능에는 억지로 점수식을 만들지 말고 판정 순서·불변 조건을 설명한다.
3. **왜 이 방법을 선택했는가?** 요구 적합성·사용 가능한 데이터·구현/실행 시간·설명 가능성 등을 실제 선택 근거와 연결한다. 의미 있는 대안이 있으면 비교하되 당시 검토한 사실과 지금 제안하는 대안을 구분한다. 실행하지 않은 대안의 성능 우위를 실측처럼 말하지 않는다.
4. **작은 사례와 기준선으로 무엇을 검증했는가?** 직접 계산/원본 사례 등 독립 기대값과 실제 결과·명령/근거를 연결한다. 비교가 필요한 기능은 단순 규칙·기존 방식 같은 기준선을 사용하고 같은 입력·제약·평가 지표에서 비교한다. 규칙 기반 기능에 불필요한 성능 벤치마크를 요구하지 않는다. 미실행이면 필요한 작은 검증을 제안하고 결과는 비워둔다.
5. **무엇을 보장하지 못하는가?** 데이터 가정·계산 범위·탐색 종료 조건·규모·미검증 경계를 구체적으로 적는다. 전체 대상을 함께 평가하는 것과 전역 최적성 증명, 여러 후보 제시와 공정성, 화면 E2E 성공과 계산 정답을 구분한다. 시간 안에 해를 못 찾은 것을 불가능 증명으로 바꾸지 않는다.

검증은 기존 근거부터 사용하고, 요청 범위 안에서 필요한 작은 관련 검사만 수행한다. 이 정리 요청만으로 알고리즘 교체·리팩터링·새 기능·별도 에이전트·외부 전송을 시작하지 않는다. 실제 요구/코드의 중대한 불일치는 설명으로 덮지 말고 위치·발생 조건·영향·다음 확인을 남긴다. 구현까지 별도로 승인되어 있으면 그 범위에서 수정하고 근거를 갱신한다.

## 남길 결과와 인계

기존 WORK/설계 문서에 `핵심 기능의 판단 근거`를 갱신한다. 사용자가 별도 문서를 지정하면 그 파일을 사용하고 동일 내용을 여러 파일에 복제하지 않는다. 다른 세션이 그 파일을 편집 중이면 반영할 초안을 전달하고 동시 수정하지 않는다.

다섯 질문의 답을 짧게 적고, 중요한 주장에는 요구 출처·코드 위치·실행 근거를 연결한다. 마지막에 다음을 덧붙인다.

- **설명 요약:** 결정 대상 → 선택 이유 → 실제 검증 → 한계를 사용자가 짧게 말할 수 있는 문장. 미구현 개선안을 실제 구현처럼 포함하지 않는다.
- **열린 항목:** 미확인 사실, 관련 불일치, 필요한 검증을 영향 순으로 정리한다. 정리 완료와 기능 검증 통과를 구분한다.

사용자가 설명 연습을 요청하면 이 기능의 선택·반례·한계에 관한 질문을 한 번에 1~3개 묻고 실제 답을 기다린다. 답을 대신 만든 뒤 이해했다고 처리하지 않는다. 부족한 답은 실제 코드/근거로 돌아가 보완한다. AI 사용이 금지된 평가 답변 단계에는 이 skill을 사용하지 않는다.
