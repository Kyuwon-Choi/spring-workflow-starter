# 답에 따라 구현이 달라지는 질문

전부 묻는 목록이 아니다. 이미 받은 자료로 채워지지 않고 결과에 영향을 주는 항목만 고른다.

| 빈칸 | 담당자에게 묻는 문장 예 | 바뀌는 것 |
|---|---|---|
| 성공 기준 | 최근 실제 입력 한 건과, 이번 도구로 얻고 싶은 결과 한 건을 보여주실 수 있나요? | 핵심 흐름·완료 조건 |
| 현재 우회 방법 | 최근 이 문제가 생겼을 때 실제로 어떤 순서로 처리했고, 도구 밖에서 무엇을 따로 하셨나요? | 실제 병목·재사용할 기존 흐름 |
| 문제의 병목 | 지금 과정에서 시간이 가장 많이 들거나 잘못 판단하는 지점은 어디인가요? | 우선순위·불필요 기능 제외 |
| 손실과 측정 | 이 문제가 생기면 누구의 어떤 일이 지연되나요? 현재 건수/시간을 확인할 자료와 측정 기간이 있나요? | 업무 가치·측정 가능한 성공 기준 |
| 원본과 인수 | 서로 다른 값이 나오면 어느 원본/담당자 판단을 따르나요? 이후 결과를 사용하고 기준을 관리할 분은 누구인가요? | 정답 근거·운영/유지 책임 |
| 중복과 충돌 | 같은 ID에 서로 다른 내용이 오면 갱신인가요, 오류인가요? 어느 자료/시각이 기준인가요? | 키·upsert·충돌 처리 |
| 집계·분모 | 취소 1건과 완료 2건이 있으면 이 지표의 분모·분자는 각각 얼마인가요? | 제외 조건·정답 계산 |
| 시간 | 날짜는 어느 시간대 기준인가요? 마감 시각과 같은 건 포함하나요? | 파싱·경계·필터 |
| 우선순위 | 우선순위가 같을 때 어떤 순서로 처리하나요? 예외가 있나요? | 정렬·동률 규칙 |
| 범위 권한 | 제가 만든 건을 다른 담당자가 맡으면 누가 조회·수정할 수 있나요? | 생성자≠담당자, 서버 조회 범위 |
| 관리자 예외 | 본인 제출 동작을 관리자가 대신 할 수 있나요? 승인 결과 금액은 누가 입력하고 언제 계산하나요? | 엄격한 본인 동작·서버 계산 필드 보호 |
| 자기 승인·위임 | 승인자가 신청자 본인이어도 허용하나요? 위임을 취소한 직후의 요청은 어떤 기준으로 판단하나요? | 역할 충돌·위임 유효성·실행 시점 권한 |
| 규칙 변경 | 새 기준은 언제 제출한 건부터 적용하나요? 진행 중·승인 완료·반려 후 재제출 건은 각각 어떻게 하나요? | 정책 적용 시각·기존 데이터·호환성 |
| 공유 한도 | 이 한도는 건별인가요, 같은 기간의 개인/부서 전체 합계인가요? 두 건이 동시에 처리되면 어떻게 되나요? | 집계 기준·공유 자원 락·원자성 |
| 민감 필드 | 전체 목록·다운로드·이력에서도 이 필드를 같은 범위로 보여줘도 되나요? | 노출 경로·필드 제한 |
| 실패/재시도 | 접수 후 알림이 실패하면 접수도 취소하나요? 같은 요청을 다시 보내면 어떻게 되나요? | 트랜잭션·멱등성·재시도 |
| 문서 근거 | 읽을 수 없는 문서나 근거가 없는 질문은 어떤 결과로 알려드려야 하나요? | OCR/추출 실패·근거·거절 |
| 배정 | 반드시 지킬 제약과 가능하면 지킬 선호를 나눠 주실 수 있나요? 모두 충족 못 하면 무엇을 보여주나요? | hard/soft·실행 불가 결과 |
| 제출 | 결과를 누가 어떤 파일/화면/API로 받고, 저장·재현은 어느 수준까지 필요한가요? | 앱 구축 여부·저장·제출 |

좋지 않은 질문: “숨은 요구 전부 알려주세요”, “보안도 해야 하죠?”, “React로 만들까요?”

바꾼 질문: “다른 담당자가 맡은 요청의 ID를 직접 열거나 CSV로 내보내면 어떤 정보까지 허용하나요?”

질문을 보낸 뒤 **실제로 받은 답**만 담당자 확인으로 기록한다. 질문 속 예시·선택지가 그 자체로 요구가 되지 않는다.
