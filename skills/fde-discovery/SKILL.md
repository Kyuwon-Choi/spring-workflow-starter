# 요구를 알아내는 인터뷰

목적은 질문을 많이 하는 것이 아니라 결과·정책·설계를 바꾸는 불확실성을 줄이는 것이다. 사용자의 언어로 작성한다.

## 시작 자료

제공 과제·README·입출력 샘플·기존 계약·담당자 답변·남은 시간을 읽는다. 이미 확인한 자료를 매번 다시 읽거나 명시된 사실을 다시 묻지 않는다. 자료가 없으면 읽었다고 쓰지 말고 현재 정보로 질문 초안을 만든다.

업무 담당자에게는 업무 사실과 정책, 플랫폼 도우미에게는 도구·환경·제출 조건을 묻는다. 구현 방법과 라이브러리 선택은 구현 AI 및 응시자의 판단이다. 이 skill은 질문 초안을 만들며, 외부 채널에 자동 전송하지 않는다.

## 답변 한 번마다 하는 일

1. `문서 사실 / 담당자 확인 / 추론·임시 가정 / 충돌·미확인`을 구분해 기록한다. 근거는 파일·절 또는 대화 시점/짧은 답변 요약으로 남긴다. 확인하지 않은 업무 정책을 채우지 않는다.
2. 누가 어떤 입력으로 어떤 결과를 얻는지, 현재 가장 큰 병목과 정상 사례 한 건을 파악한다. CRUD·AI 기능·로그인을 먼저 정해 놓고 질문하지 않는다.
3. 다음 불확실성의 **답에 따라 달라지는 결과·설계·검증**을 한 줄로 적는다. 영향이 큰 정책·정답 기준·제출 형식을 먼저 묻고, 이미 답한 질문과 영향 없는 취향 질문은 뺀다.
4. 다음에 보낼 질문은 보통 연결된 1~3개다. 첫 질문의 답이 뒤 질문을 바꾸면 첫 질문만 보낸다. 실제 사례의 입력→기대 결과나 경계 사례를 제시해 답을 구한다. 정답을 유도하거나 고정 질문 목록을 소진하지 않는다.
5. 답을 받은 항목을 요구 ID와 관찰 가능한 완료 조건으로 바꾼다. 질문 수나 합의 여부를 공식 점수로 표현하지 않는다.

실제 사례가 비어 있으면 최근 한 건의 사건 → 현재 우회 방법 → 지연/오류와 비용 → 영향을 받는 사람 → 예외/경계 순으로 좁힌다. 이미 자료에 있으면 다시 묻지 않는다. 원본 데이터와 정답을 정하는 주체, 해결하지 않을 때의 손실, 인수 후 사용자/유지 담당자를 필요한 범위에서 확인한다. 재무·리드타임·수요 등 사업 관점은 관련 있는 것만 쓴다. 특정 단어를 일정 시간 금지하거나 모든 관점을 소진하지 않는다.

성공 기준은 기능의 입력/기대값과 업무 개선을 구분한다. 업무 지표에는 현재값·목표·측정 자료/기간을 확인된 만큼 기록한다. 숫자가 없으면 미확인으로 두고 실제 사례의 관찰 가능한 결과를 사용한다. 추정 절감률이나 대회 채점 기준을 만들지 않는다.

질문 유형별 예시는 필요할 때만 [질문 카드](references/question-cards.md)를 읽는다.

## 매 응답 형식

- **담당자에게 보낼 문장:** 그대로 복사 가능한 짧은 질문만. 내부 추론이나 구현 지시를 섞지 않는다.
- **이 질문의 이유:** 어떤 결정과 검증이 달라지는지 응시자에게 짧게 설명한다.
- **기록 갱신:** 새 사실/수정된 요구 ID·근거·가정·충돌만 기록한다. 기존 WORK/요구 문서가 있으면 이어 쓴다.
- **지금 진행 가능한 일:** 답변을 기다리는 동안 독립적으로 가능한 범위. 실제 구현은 사용자가 요청한 범위에서만 한다.

## 모호함과 충돌

‘최신’, ‘중복’, ‘우선’, ‘완료’는 실제 키·시각·동률·포함/제외 기준으로 좁힌다. 서로 충돌하는 답은 양쪽 근거와 충돌 사례를 제시하고 적용 범위를 확인한다. 최신 답이라는 이유만으로 이전 필수 조건을 지우지 않는다.

담당자가 모르면 선택지와 결과 차이를 설명하고 임시 가정을 명시한다. 권한·파괴적 변경·정답을 바꾸는 정책을 답 없이 확정하지 않는다. 답변 채널이 없으면 문서 근거와 미확인을 분리하고 가역적인 최소 범위를 진행한다.

## 계획으로 넘길 때

목표·사용자·입출력/제출물·정상 기대값·핵심 정책·권한/노출 범위를 설명할 수 있으면 [서면 합의](references/agreement.md)에 따라 짧은 합의안을 만든다. 문제·병목·성공 기준·이번 범위/제외·제약·미확인을 묶고 실제 담당자 확인을 요청할 문장을 제공한다. 외부 전송은 하지 않는다. 답변 전에는 `확인 대기`로 두고, 실제 답과 적용 범위가 확인된 항목만 `확인`으로 기록한다.

합의 답변을 기다려도 제공 코드 실행·자료 탐색과 확정된 독립 범위의 계획은 이어간다. 정답·권한·비가역 동작을 바꾸는 미확인만 해당 구현을 막는다. 담당자 채널이 없으면 `문서 근거/담당자 확인 불가`를 남기고 가역적인 범위를 진행한다. 제공 자료에 권한 기능이 필요 없으면 새 인증 요구를 만들지 않는다. 질문에 보통 10~15분을 배정하되 공식 제한처럼 강제하지 않는다.

인수인계에는 다음을 담는다: 목표/성공 사례, `R-ID | 요구 | 출처·확인 상태 | 완료 조건·예상값`, 이번 범위와 제외 이유, `U-ID | 미확인 | 영향 | 임시 처리 | 답변 필요 시점`, 환경·제출 제약과 시간. 계획 skill이 없어도 이 기록만으로 이어갈 수 있어야 한다.

AI 금지 단계에는 이 skill을 사용하지 않는다. skill의 존재가 시험 반입이나 외부 전송 허용을 뜻하지 않는다.
