# 질문·합의·계획·핵심 기능 설명 skill 사용

세 skill을 작업 단계에 맞춰 사용한다. [fde-discovery](fde-discovery/SKILL.md)는 실제 자료와 담당자 답을 질문·요구·서면 합의안으로, [fde-planning](fde-planning/SKILL.md)은 합의/미확인을 기반 선택·첫 흐름·검증·중간 확인·제출 계획으로 연결한다. [fde-core-review](fde-core-review/SKILL.md)는 핵심 기능의 결정 대상·조건/목표·선택 이유·독립 검증·한계를 실제 코드와 근거로 정리한다. 진행 기록은 기존 WORK/설계 문서에 모으며, skill을 사용한다고 별도 세션이 자동 생성되지는 않는다.

## 제공 과제 폴더에 설치

사전 skill 사용이 허용된 작업 단계에서 키트를 가져온 뒤 저장소 최상위에서 실행한다. 제공 코드가 있으면 그 과제 폴더를 지정하고, 모듈형으로 만든 solution에서는 그 경로를 명시한다. 인자 생략은 기존 전체 참고 앱 자체에서 작업할 때만 사용한다. 설치 때문에 제공 코드를 교체하지 않는다.

```bash
./scripts/install-skills.sh /path/to/existing-task
# 이 키트 자체가 작업 폴더일 때:
# ./scripts/install-skills.sh
```

설치기는 지정 폴더의 `.agents/skills/`에 세 디렉터리 전체를 복사한다. 기존 내용이 다르거나 링크이면 어떤 스킬도 복사하기 전에 중단하며, 같은 내용이면 유지한다. 개인 설정·계정·네트워크를 변경하지 않는다. 갱신 충돌은 실제 차이를 비교한 뒤 필요한 파일만 반영한다.

Codex 공식 문서는 프로젝트의 `.agents/skills` 탐색과 명시적 skill 호출을 안내한다. 실제 제공 인터페이스에서 세 skill이 보이는지 확인한다. CLI/IDE에서는 `/skills` 또는 `$`로 선택할 수 있으며, 다른 UI는 표시되는 skill 선택 기능을 사용한다. 변경이 안 보이면 Codex 재시작을 시도할 수 있지만 진행 중인 시험 세션을 잃을 위험이 있으면 아래 파일 읽기 방식으로 바로 진행한다. [OpenAI Docs · Build skills](https://learn.chatgpt.com/docs/build-skills).

현재 PC에 설치한 skill은 시험 환경으로 자동 이전되지 않는다. 개인 skills 경로는 환경마다 다를 수 있으므로 시험에서는 지정 과제 폴더 설치 또는 파일 직접 읽기 중 실제 지원되는 방법을 쓴다. 설치 성공과 Codex가 skill을 인식한 것은 별개다.

## 첫 호출과 답변 반영

```text
$fde-discovery
과제/자료: [원문·경로]
이미 받은 담당자 답: [실제 답 또는 없음]
작업 종료/전체 마감/남은 시간: [실제 값]
기록: [과제 폴더]/WORK.md
실제 사례와 현재 처리의 빈칸부터 다음 질문을 골라줘.
답을 대신 만들지 말고 합의안을 준비하되 실제 확인 전에는 확인 대기로 둬.
```

응시자가 질문을 담당자에게 보내고 실제 답을 같은 대화에 붙인다. 새 답과 수정 요구만 기록하고 다음 질문 또는 합의안으로 이어간다. 구현 AI가 담당자 역할까지 대신하지 않는다.

## 합의 후 계획과 구현

```text
$fde-planning
요구/합의와 실제 담당자 답: [WORK.md 경로]
기존 코드/허용 키트: [실제 경로]
작업 종료/전체 마감: [실제 값]
필수 요구를 보존하면서 첫 입력→실제 결과부터 계획해줘.
중간 확인·수용 확인·검증·수정·제출 시간을 포함하고
STATE의 현재 근거와 다음 전환 조건을 WORK.md에 남겨줘.
```

계획이 맞으면 “이 계획대로 첫 흐름부터 구현하고, 단계 전환과 중간 확인 때 WORK.md를 갱신해줘”라고 지시한다. 이미 구현까지 지시했다면 다시 허락을 요청하지 않고 승인된 범위를 이어간다. 담당자 확인이 필요한 시점에는 보낼 입력·실제 결과·한계·질문을 받고 응시자가 전달한다. 답변 대기 중 독립 작업은 진행한다.

## 핵심 기능 구현 후·주요 변경 후·제출 전

```text
$fde-core-review
대상 핵심 기능: [기능과 실제 경로]
요구/실제 담당자 답: [WORK.md 경로]
관련 검증 결과: [실제 경로 또는 미실행]
결정 대상·필수 조건과 목표·방법 선택 이유·작은 사례/기준선 검증·한계를 정리해줘.
각 주장에 실제 코드와 근거를 연결하고 미확인/미실행은 따로 표시해줘.
기록은 기존 WORK.md에 반영하고 구현을 바꾸지는 마.
```

알고리즘 세션의 인계나 구현 세션의 설명 준비에 사용할 수 있다. 같은 기록 파일의 동시 수정은 피한다. 설명 연습까지 원하면 “정리 후 질문을 한 번에 1~3개씩 해주고 내 답을 기다려줘”를 덧붙인다. 화면 E2E 성공과 계산 정답, 후보 제시와 공정성, 전체 평가와 전역 최적성 증명을 구분한다. 검증이 없으면 좋은 설명으로 대신하지 않고 빈 근거를 표시한다.

## skill이 목록에 안 보일 때

등록 여부를 추측하지 말고 구현 AI에 실제 경로를 지정한다.

```text
[키트 경로]/skills/fde-discovery/SKILL.md를 읽고 그 절차로 인터뷰를 준비해줘.
그 파일이 연결한 참고 자료는 필요한 단계에만 읽어줘.
기록은 [과제 폴더]/WORK.md 하나를 사용해줘.
```

계획 단계에는 `skills/fde-planning/SKILL.md`, 핵심 기능 정리에는 `skills/fde-core-review/SKILL.md`로 바꾼다. 이는 파일을 읽는 방식이며 skill 등록 성공을 뜻하지 않는다. 디렉터리 이름을 바꾸거나 SKILL.md만 복사하면 상대 경로의 참고/양식이 빠질 수 있으므로 전체 디렉터리를 유지한다.

[전체 작업 절차](../docs/WORKFLOW.md) · [단계별 프롬프트](../docs/PROMPTS.md) · [WORK 양식](../docs/templates/WORK.md). skill 사용 허용은 멀티 세션·외부 전송·Computer Use 허용과 별개다. AI 금지 사후 답변 단계에는 사용하지 않는다.
