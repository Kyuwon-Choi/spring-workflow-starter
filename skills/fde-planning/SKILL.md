# 요구에서 실행 가능한 계획으로

확인된 요구와 실제 코드·런타임을 연결한다. 계획을 요청받았다면 계획과 기록을 만들고, 구현까지 승인되어 있으면 첫 작은 작업으로 이어간다. 새 저장소 공개·배포·외부 전송을 계획 승인에 포함시키지 않는다.

## 계획 전 확인

- 과제·기존 README/API/테스트·데이터 샘플·요구 기록을 읽는다. 설치/코드/검증을 직접 확인하지 않았으면 미확인으로 적는다.
- 요구마다 출처와 `확정/가정/충돌`을 보존한다. UI 문구나 기술 선택을 새로운 현업 요구로 바꾸지 않는다. 요구가 부족하면 결과를 크게 바꾸는 질문을 남기고 독립적인 범위를 계획한다.
- 현재 시각/남은 시간, 작업 타이머 종료, 전체 마감, 제출 단계와 후속 단계 예약을 구분한다. 주어지지 않은 시각을 만들어내지 않는다. 후속 질문 30분 등 실제 안내가 있는 경우 전체 마감에서 준비 대기와 제출 여유까지 빼고 작업 종료 목표를 잡는다. 전체 운영 시간을 전부 구현 시간으로 쓰지 않는다.

## 기반 선택

기존 프로젝트를 주었다면 해당 계약·스택에서 최소 변경한다. 새 과제는 **핵심 산출물**을 기준으로 업무 도구 / 배치 분석 / 문서 처리 / 제약 최적화 / 외부 연동으로 나누되 한 유형에 억지로 맞추지 않는다.

각 필수 요구에 `그대로 사용 / 정의 변경 / 확장 구현 / 부적합·다른 기반`을 매긴다. 재사용의 근거는 실제 API·타입·실행 상태다. FDE 키트와 특수 모듈의 경계는 필요할 때 [적합성 점검](references/kit-fit.md)을 읽는다. 레포 카드는 제공된 경우에만 읽고, 목록에 있다는 이유로 실행 가능한 것으로 간주하지 않는다.

## 계획 산출물

기존 로직에 추가 요구·정책 변경이 들어오거나 조직/위임/다단계 승인 조건이 있으면 [요구 변경 대응](references/change-control.md)을 읽고 적용 시점·기존 데이터·유지할 규칙과 회귀 범위를 먼저 정한다.

기존 WORK/요구 문서가 있으면 중복 파일을 만들지 말고 갱신한다. 없으면 [작업 기록 양식](assets/WORK.md)을 과제 경로에 적용한다. 핵심은 다음 연결이다.

`R-ID·출처 → 관찰 가능한 완료 조건 → 최소 변경 위치 → 검증 입력·독립적인 예상값 → 실제 결과`

1. 목표·필수 산출물·제약·남은 미확인과 기반 선택 이유를 짧게 적는다.
2. 첫 핵심 흐름을 **실제 입력 → 업무 규칙 → 관찰 가능한 결과**로 정의한다. 화면만 그리기, mock 응답, 실행하지 않은 구현은 첫 흐름 완료가 아니다. 분석 과제라면 입력 파일→계산→제출 파일이 첫 흐름일 수 있다.
3. 첫 흐름 → 남은 필수 요구 → 관련 예외/권한·수정 → 최종 제출 점검 순으로 작은 작업을 만든다. 작업마다 요구 ID, 파일/기능(미확인이면 탐색 대상), 완료 조건, 실제 검증, 대략 시간과 의존성을 붙인다. 보안·무결성 조건은 해당 기능과 함께 구현하고 끝에 처음 붙이지 않는다.
4. 남은 총시간 안에서 합산하고 설치·검증·수정·제출 여유를 남긴다. 보통 첫 흐름을 구현 시간 전반부에 실행하도록 줄인다. 시간이 부족해도 필수 조건을 임의로 선택 기능으로 바꾸지 말고 미완료와 영향을 드러낸다.
5. 미확인 정책이 막는 작업만 보류한다. 설치가 예상 시간을 넘거나 첫 흐름이 지연되면 기존 실행 경로/검증된 최소 대안을 비교하고 재계획한다. 필수 외부 호출을 가짜 성공으로 바꾸지 않는다.

## 검증 설계

정상 사례의 예상값은 담당자 사례나 고정 입력에서 직접 계산한다. 구현한 함수로 예상값도 생성하면 정답 검증이 되지 않는다. 요구에 따라 중요한 경계·실패·권한·중복/동시성 검사를 고른다. 모든 과제에 인증·OCR·전체 테스트를 추가하지 않는다.

기존 관련 테스트와 직접 실행을 조합한다. UI가 산출물이면 사람의 실제 화면 확인을 별도로 남긴다. 시험에서 Computer Use가 금지되면 자동 조작 계획을 넣지 않는다. 실패 수정 후 관련 재검증을 하고, 근거 없이 전체 검사 반복을 예약하지 않는다.

요구가 바뀌면 해당 요구와 영향받는 작업·예상값·시간만 갱신한다. 진행 상태는 `미실행 / 실패 / 부분충족 / 통과`로 기록한다. 최종 기록에는 재사용 출처·변경 이유·실제 실행 근거·한계와 다음 작업을 남겨 응시자가 자기 선택을 설명할 수 있게 한다.

AI 금지 사후 답변은 사람이 직접 수행한다. 이 skill의 설치가 시험 사용 허용을 뜻하지 않는다.
