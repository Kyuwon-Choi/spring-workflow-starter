# 키트를 고르는 경계

현재 프로젝트의 실제 문서·코드와 다시 대조한다. 아래는 Spring FDE Workbench 준비 버전의 확인 범위이며 모든 FDE 제품의 공통 사양이 아니다.

| 요구 | 시작점 | 반드시 확인할 차이 |
|---|---|---|
| 스칼라 필드, 단일 참조, 폼·목록·검색 | 정의 기반 Workbench | 지원 타입·길이·입력·목록 한도, 참조 선택 100개 |
| 승인·반려·상태별 액션 | 정의의 actions | 역할·현재 상태·선행 조건·필수 입력·version |
| 생성자 본인/전체 권한 | OWN/ALL + managerRoles | 실제 담당자·부서·테넌트·필드 권한과 다름 |
| 관리자가 대신 할 수 없는 본인 동작 | 액션 OWNER_ONLY | OWN은 관리자 예외를 허용하므로 본인만 제출 등에는 그대로 쓰지 않음 |
| 서버 계산·관리자 기록 필드 | 필드 readOnly | 생성 API/CSV/폼 입력 금지, 신뢰된 액션만 기록; 역할별 열람 제한은 별도 |
| 회사·부서·프로젝트/기간 위임·필드 노출 | 선택형 FdePolicy / EnterpriseAccess | 예제는 평면 부서·명시적 프로젝트·한 계정 한 회사, 실제 정책과 검증 필요 |
| 단계별 승인·시행일·기존 진행 건 유지 | EnterpriseCommands / 변경 불가 규칙 버전 | 현재는 제출 시 버전 고정·반려 재제출 때 현재 버전 선택; 다른 소급 정책이면 변경 |
| 여러 요청의 공유 예산 | 회사 공통 잠금 + 최종 승인 때 차감 | 실제 요청/예산/이력 롤백·동시성 검증 경로 있음. 회사별 직렬화의 처리량 한계 고려 |
| 한 객체의 계산/수량 변경 | 신뢰된 Java FdeExtension | 순수 계산·최종 검증·원자적 이력 경계 |
| CSV 일괄 생성·내보내기 | Workbench CSV | 100행 입력·1000행 출력, 갱신/충돌 병합 기능과 다름 |
| 여러 파일 결합·갱신 이력 정제·정답 집계 | DuckDB 분석 recipe | 현재 recipe는 단순 그룹 집계, dedup/join/시각 규칙은 새 구현 |
| 문서 본문·표·페이지 근거 추출 | Tika 등 구체적 예제 | 소스 확인과 실제 실행 구분, 스캔 문서는 OCR 별도 |
| 인원/시간/설비의 복합 배정 | Timefold Spring 예제 | hard/soft 목적함수·미배정·solver 제한·재현성 |
| 기존 API 수정·외부 동기화 | 제공 저장소 | 계약 유지, 멱등성·동시성·outbox/재시도 별도 |
| 실제 AI/RAG | 제공 모델/허용된 SDK | 실제 호출·근거·오류/한도·자료 전송 제약 |

예제 도메인명을 바꾸는 것으로 부서 권한이나 다대다 배정이 생기지 않는다. 외부 네트워크 부작용은 단일 객체 DB 트랜잭션 성공과 같은 뜻이 아니다. 구현이 필요한 항목을 정의 변경으로 축소하지 않는다.

시간 내 필수 요구를 충족하는 경로를 비교한다. 현재 키트를 쓰는 것이 계약 수정·설치·의존성 비용을 늘리면 해당 요구에는 선택하지 않는다. 단순 분석 파일이 결과물인 경우 로그인과 웹 DB를 추가할 근거부터 확인한다.
