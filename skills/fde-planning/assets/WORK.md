# 작업 기록

## 목표와 시간

- 사용자 / 문제 / 정상 사례의 입력과 기대 결과:
- 필수 산출물 / 제출 방식:
- 현재 시각·남은 시간 / 작업 타이머 종료 / 전체 마감:
- 후속 단계·제출 여유 / 구현 종료 목표:
- 환경·사용 가능 자료·금지 도구 / 확인 근거:
- 이번 범위 / 제외 이유:

## 문제와 서면 합의

- 해결할 핵심 간극 한 문장 / 연결된 필수 요구 ID:
- 최근 실제 사례 / 현재 처리·우회 방법:
- 병목·원인 / 근거 또는 가설 / 해결하지 않을 때의 손실:
- 원본 데이터·정답 기준 / 판단 주체:
- 기능 성공 사례: 실제 입력 → 기대 결과:
- 업무 개선 지표: 현재값 / 목표 / 측정 자료·기간 / 확인 근거(없으면 미확인):
- 결과 사용자 / 인수 후 운영·유지 담당자(없으면 미확인):
- 만들 것 / 제외할 것·이유 / 제약 / 남은 질문:
- 담당자에게 보낸 합의안 버전·위치:
- 합의 상태: 초안 / 확인 대기 / 부분 확인 / 확인 / 수정 필요 / 확인 불가:
- 실제 답변 시점·요약 / 확인된 범위 / 남은 미확인:

숫자·담당자 답변을 만들지 않는다. 일부 답변을 전체 합의로 확대하지 않는다. 핵심 간극에 집중해도 명시된 필수 요구를 지우지 않는다.

## 현재 단계와 전환

- STATE: DISCOVERY / AGREEMENT / SCAFFOLD / E2E_V0 / MID_CHECK / ACCEPTANCE / SUBMISSION:
- 현재 단계에서 확보한 근거 / 대기 중인 확인:
- 다음 단계 진입 조건 / 다음 작은 작업:
- 실제 남은 시간 / 검증·제출 예약 / 지연 시 재계획:

| 전환 시각 | 이전→다음 STATE | 실제 근거·남은 대기 | 요구 이탈·근거 없는 완료·반례 누락 점검 | 남은 시간과 다음 작업 |
|---|---|---|---|---|

미응답을 승인으로 해석하지 않는다. 답이 필요한 구현만 보류하고 독립 준비는 이어간다. 단계 진입과 단계 완료는 다르며, 전환은 의미 있는 시점에만 기록한다.

## 요구와 검증

| ID | 요구·출처·확정/가정/충돌 | 관찰 가능한 완료 조건 | 재사용 판단 | 변경 파일/기능 | 검증 입력·예상값 | 실제 실행·근거 | 상태 |
|---|---|---|---|---|---|---|---|

출처는 문서 위치 또는 담당자 답변 시점/요약으로 연결한다. 재사용 판단은 그대로 사용/정의 변경/확장 구현/부적합·다른 기반. 상태는 미실행/실패/부분충족/통과. 미확인 정책과 실행 상태를 구분한다.

|---|---|---|---|---|---|

## 실행 큐

### 세션을 나눌 때의 계약

- 통합/WORK 최종 작성 담당 / 다른 세션의 수정 파일·소유권:
- 공유 API·계산 입력/출력 / ID·단위·방향·시간 기준·오류 상태:
- 현재 코드·데이터·파라미터 버전 / 이전 결과와 구분:
- 실제 담당자 답·변경된 조건 / 영향받는 요구·코드·테스트 / 반영 상태:
- 인계할 실제 명령·기대/실제·근거 / 미실행·다음 담당:

기본은 단일 세션이며 분담할 때만 채운다. 같은 파일/공유 빌드·DB의 동시 변경을 피하고 실제 파일과 결과를 대조한다.

| 순서 | 요구 ID | 작업・파일/기능 | 대략 시간・의존성 | 완료 조건・검증 | 상태 |
|---|---|---|---|---|---|

- 설치/오류 수정/최종 검증/제출 예약 시간과 합계:
- 첫 흐름 지연·환경 실패 시 줄일 범위/전환 기준:

## 계산·AI·반영 경계

- 정확한 규칙으로 계산/판정할 항목 / 구현·검증 위치:
- AI가 필요한 경우 그 역할 / 입력·근거 / 형식·업무 검증:
- AI 실패·불확실성 표시 / 사람 확인 / 실제 데이터 반영 조건:

AI가 필요 없으면 해당 없음으로 둔다. 모델 출력만으로 권한·승인·원장 변경을 확정하지 않는다.
