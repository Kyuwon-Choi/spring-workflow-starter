# 과제 시작부터 제출까지

제공 환경 안에서 이 공개 가이드를 읽고 사용한다. 개인 PC 설치가 자동으로 이전되지는 않는다. 실제 과제 안내의 스택·필수 파일·제출 경로·시간·도구 제한이 우선한다. 아래 기록용 WORK는 공식 제출 양식이 아니며 필수 문서를 대체하지 않는다.

## 1. 제공 코드와 작업 위치 확인

제공 터미널에서 Codex를 열고 실제 작업 폴더·README·데이터·기존 코드·실행/제출 안내를 먼저 확인한다. 제공 프로젝트가 있으면 API와 스택을 유지한다. 이 키트는 별도 참고 경로에 가져오고, 새 프로젝트의 기반으로 쓸지는 계획 단계에서 판단한다.

첫 요청 예:

```text
현재 과제 폴더의 README·자료·기존 코드·실행 안내를 읽어줘.
공개 참고 키트:
https://github.com/Kyuwon-Choi/spring-workflow-starter
브랜치: codex/public-starter

허용된 작업공간의 별도 경로에 이 키트를 Clone하고 실제 경로를 알려줘.
제공 코드와 공식 제출 문서는 덮어쓰지 마.
키트의 docs/START-TO-FINISH.md와 skills/fde-discovery/SKILL.md를 읽어줘.
참고 파일은 필요한 단계에서만 읽고, 업무 기능 구현은 아직 하지 마.
제공 코드 기동 확인처럼 독립적인 준비는 진행해도 돼.
확정 사실·필수 산출물·환경 제약·다음 담당자 질문부터 정리해줘.
작업 타이머 종료: [실제 값], 전체 종료: [실제 값]
```

정보가 이미 명시되어 있으면 다시 질문하지 않는다. 플랫폼 조작/제출은 플랫폼 도우미에게, 업무 사례와 정책은 담당자에게, 구현은 Codex에 요청한다.

## 2. skill 준비와 인터뷰

키트 최상위에서 `./scripts/install-skills.sh /실제/과제폴더`를 실행하면 `.agents/skills`에 두 skill이 복사된다. 신규 과제를 이 키트에서 시작할 때는 인자를 생략한다. 실제 인식 여부를 확인하고, 목록에 없으면 재시작에 시간을 쓰기보다 SKILL.md 경로를 직접 읽힌다. [설치 상세](../skills/README.md).

```text
$fde-discovery
과제/데이터: [실제 경로]
담당자에게 실제 받은 답: [없음 또는 원문]
작업 기록: [과제 폴더]/WORK.md
남은 시간: [실제 값]

실제 사례·현재 처리·손실·성공 기준 중 자료에 없는 것부터 질문해줘.
담당자에게 보낼 문장과 그 답이 바꾸는 결정을 구분해줘.
답을 대신 만들지 말고 이미 문서에 있는 사실은 다시 묻지 마.
```

응시자가 질문을 실제 담당자에게 보내고 받은 답을 같은 Codex 대화에 붙인다. 질문은 보통 연결된 1~3개이며, 첫 답에 따라 다음 질문이 바뀌면 하나만 보낸다. 해결책을 먼저 정하지 말고 최근 실제 한 건·현재 우회 방법·지연/오류·원본·영향받는 사람·중요한 경계부터 파악한다.

답변 반영 요청:

```text
담당자의 실제 답변:
[원문]
WORK.md에 문서 사실/담당자 확인/가정/충돌을 구분해 갱신해줘.
구현이나 정답이 달라지는 다음 질문만 고르고, 충분하면 합의안을 작성해줘.
```

## 3. 문제 전체를 서면 확인

Codex가 핵심 문제·병목·원본·성공 사례·범위/제외·제약·미확인을 묶은 합의안을 만들면 응시자가 담당자에게 보낸다. [합의 카드](../skills/fde-discovery/references/agreement.md)를 사용하고 실제 답변과 확인 범위를 WORK에 기록한다.

확인할 문장 예:

> 이번에는 [핵심 문제]를 해결하고, [원본]의 [입력]이 [기대 결과]로 처리되면 성공으로 보겠습니다. [필수 범위]를 만들고 [제외와 이유]는 포함하지 않겠습니다. [정책]은 아직 확인이 필요합니다. 잘못 이해한 부분이나 빠진 필수 조건이 있으면 알려주세요.

모르는 현재값/개선율은 미확인으로 둔다. 일부 답변을 전체 동의로 확대하지 않는다. 무응답은 합의가 아니며, 답이 필요한 구현만 보류하고 확정된 독립 작업은 진행한다.

## 4. 요구를 실행 계획에 연결

```text
$fde-planning
WORK.md의 실제 요구·합의·미확인을 읽어줘.
제공 코드: [경로], 참고 키트: [경로]
남은 작업 시간/전체 마감/후속 단계: [실제 값]

필수 요구마다 완료 조건·수정 위치·독립 예상값·검증 방법을 연결해줘.
그대로 사용/정의 변경/확장 구현/다른 기반으로 판단하고,
가장 중요한 실제 입력→결과 흐름을 먼저 실행하도록 계획해줘.
중간 확인·남은 필수 요구·경계/권한·오류 수정·문서·제출 시간을 합산해줘.
STATE의 현재 근거·대기 중인 확인·다음 전환 조건을 WORK.md에 남겨줘.
```

응시자는 필수 요구 누락, 불필요한 기능, 늦은 첫 실행, 근거 없는 정책을 확인한다. 기존 코드 수정이면 원래 구조에서 시작한다. 신규 업무 도구면 키트를 검토하고, 파일 정답/분석·문서·배정 등이 핵심이면 [도구 선택](REPO-CHOOSER.md)을 비교한다. 목록에 있는 도구가 모두 실행 검증된 것은 아니다.

정확한 금액·권한·상태·자격 판정은 규칙과 코드로 검증한다. AI 기능이 필요하면 모델 결과의 근거·형식/업무 검증·실패·사람 확인·실제 반영 경계를 정한다. AI가 필요 없으면 추가하지 않는다.

## 5. 첫 흐름 구현과 직접 화면 확인

계획이 적합하면 다음을 보낸다. 이미 구현까지 지시했으면 승인된 범위를 다시 허락받을 필요는 없다.

```text
이 계획대로 첫 핵심 흐름부터 구현하고 실제 실행해줘.
유지할 계약: [API·기존 동작·권한·데이터]
첫 검증 입력→독립 예상값: [내용]
정상 결과와 중요한 실패/권한 조건을 함께 확인해줘.
실행 결과·실패·미검증을 구분하고 선택 이유를 WORK.md에 남겨줘.
첫 흐름이 실행되면 담당자에게 보낼 입력·실제 결과·한계·확인 질문을 준비해줘.
```

이 키트를 신규 기반으로 선택한 경우의 설치·빌드·실행은 다음과 같다. 제공 프로젝트에는 그 프로젝트의 명령을 사용한다. 설치가 막히면 실제 오류와 비용을 비교하고, 근거 없이 같은 전체 명령을 반복하지 않는다.

```bash
./npmw ci --no-audit --no-fund
./npmw run webapp:build:dev
./mvnw -ntp -Dskip.installnodenpm -Dskip.npm verify
./scripts/preview.sh 8080
```

서버 터미널을 유지한다. 위 실행기는 0.0.0.0에 바인딩한다. 플랫폼 Browser의 PORT에는 서버 로그의 실제 포트, URL에는 `/fde`를 입력하고 원형 화살표로 연결한다. 새 화면 경로를 만들었으면 그 경로를 사용한다. [미리보기](PREVIEW.md).

응시자가 화면에서 입력·저장·동작·이동을 직접 확인한다. 요구에 따라 새로고침 후 결과 보존, 다른 계정의 접근, 실패 시 데이터 불변도 본다. HTTP/테스트 성공과 실제 화면 확인은 따로 기록한다. Computer Use가 금지된 평가에서는 자동 화면 조작을 요청하지 않는다.

## 6. 중간 확인과 추가 요구

응시자가 실제 사례와 관찰한 결과를 담당자에게 보여주고 맞는 업무 결과인지 확인한다. “괜찮나요?” 대신 특정 입력의 결과와 예외 처리 판단을 묻는다. 실제 답을 Codex에 전달해 확인 범위·요구·검증·시간을 수정한다.

```text
추가 요구/중간 확인의 실제 답:
[원문]
기존 요구를 지우지 말고 바뀌는 조건과 충돌을 정리해줘.
기존 데이터·진행 중 건·권한·적용 시점·계산/상태에 미치는 영향을 확인해줘.
영향받는 요구 ID·코드·독립 예상값·관련 회귀 검증·남은 시간을 갱신해줘.
정책이 미확인이면 해당 변경만 보류하고 독립 작업을 이어가줘.
```

이후 남은 필수 요구를 작은 단위로 구현한다. 기본은 단일 세션이며 별도 세션/에이전트는 사용자 지시와 허용 범위가 있을 때만 사용한다. 필요하면 [읽기 전용 검토 카드](PROMPTS.md)를 전달하고 지적을 실제 재현/검증으로 확인한다.

## 7. 최종 검증·수용·설명 준비

필수 흐름을 완성한 뒤에는 중요한 경계·실패·권한과 발견된 오류 수정을 우선한다. 모든 과제에 모든 보안 기능/전체 테스트를 추가하지 않는다. 적용되는 정상/잘못된 입력/상태 위반/다른 사용자 접근/중복·오래된 버전/실패 시 불변 조건을 고른다.

```text
WORK.md의 필수 요구와 실제 결과를 대조해줘.
각 요구를 통과/부분충족/실패/미실행으로 기록하고 실제 근거를 연결해줘.
발견된 중요한 오류부터 수정하고 관련 검증을 다시 실행해줘.
필수 제출 문서는 과제 안내의 파일명·양식을 따르고,
실행 명령·핵심 파일·재사용/직접 구현 범위·선택 이유·실제 검증·한계를 정리해줘.
담당자에게 최종 확인할 실제 사례와 남은 한계를 준비해줘.
실행하지 않은 검사·측정하지 않은 개선율·받지 않은 수용 답을 만들지 마.
```

제출물 확정 전에 응시자가 다음을 자기 말로 설명할 수 있는지 확인한다: 핵심 문제와 질문 이유, 선택한 기반, 입력→규칙/계산→저장/출력, 중요한 권한/예외, 실제 검증, 남은 한계. AI 금지 단계가 시작된 뒤에는 AI로 답을 만들지 않는다.

## 8. 제출부터 최종 종료까지

플랫폼의 실제 제출 절차를 따른다. 제출 미리보기를 여는 시점에도 타이머가 흐를 수 있으므로 여유를 확보한다. 필수 파일의 실제 경로·저장 완료·실행/산출물을 확인하고, 수정 불가 확정 버튼은 마지막으로 누른다. 후보 준비·제출물 확정·최종 제출 완료를 구분한다.

이후 AI 금지 서술형이 있으면 AI/skill 사용을 중단하고 직접 입력한다. 질문의 전제와 실제 구현이 다르면 그 차이를 밝히고, 구현 위치→선택 이유→실제 검증→한계를 중심으로 답한다. 미실행을 검증 완료로 말하지 않는다. 이전 문항 복귀나 복사/붙여넣기 가능 여부는 실제 안내를 따른다.

최종 처리/업로드가 끝난 뒤 완료 화면과 제출 ID·시각·파일 수/크기를 실제 표시된 범위에서 확인한다. 그전에는 브라우저·감독 연결을 종료하지 않는다.

## 진행이 막힐 때

- Codex 승인 대기라면 요청 내용을 확인해 응답한다. 실행 중이라면 중복 요청을 보내지 않는다. 완료 출력은 실제 결과와 대조한다.
- 접속/반복 오류는 발생 시각·단계·직전 동작·오류 문구를 기록해 플랫폼의 신고 기능을 사용한다. 비밀번호·키·토큰은 넣지 않는다.
- 미리보기는 서버 오류/종료→실제 포트→0.0.0.0→경로 순으로 확인한다. 서버 탭을 임의로 닫지 않는다.
- 에디터와 AI가 같은 파일을 수정해 충돌하면 양쪽 내용을 비교한다. 오래된 에디터 내용을 무심코 저장하지 않는다.
- 세션을 바꾸기 전에 WORK에 마지막 실행 명령·결과·오류·다음 작업을 남긴다. 새 세션은 WORK와 실제 파일을 대조하고 이어간다.
- 시간이 부족하면 선택 기능을 줄이고 필수 요구·검증·제출을 재계획한다. 필수 요구를 조용히 제외하거나 가짜 결과로 완료 처리하지 않는다.
