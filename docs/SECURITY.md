# 보안과 예외 검증

로컬 준비용 키트의 구현 경계와 업무 적용 때 확인할 항목이다. 운영 보안 인증이나 전체 취약점 감사 결과를 뜻하지 않는다. 요구에 맞는 허용/거부 사례와 실제 저장 결과를 함께 검사한다.

## 적용된 경계

- 서버 인증 주체를 사용한다. 생성 시 owner/state/version과 조직 전용 필드를 클라이언트가 지정하지 못한다.
- 타입·범위·필수·알 수 없는 필드·참조 접근·고유 업무 키·현재 상태·version을 검사한다.
- 일반 권한은 역할/ALL/OWN/OWNER_ONLY이며, 복잡한 조직 권한은 선택형 FdePolicy로 SQL과 단건 동작에 적용한다.
- 조직 정책은 목록/건수/CSV/이력/비공개 필드/검색 색인을 같은 범위로 설계한다. 내부 메모는 모든 역할의 텍스트 검색에서 제외한다.
- 회사·권한·위임 변경과 예산/승인을 직렬화하고 요청·예산·이력 변경을 같은 DB 트랜잭션으로 처리한다.
- CSV 수식 보호와 행/길이 제한이 있다. 정의/확장은 신뢰된 소스만 등록하고 요청에서 SQL/스크립트를 실행하지 않는다.
- 기본 미사용 샘플 CRUD API는 닫혀 있다. 원본 JHipster CRUD 전체가 업무 키트의 공개 API라고 가정하지 않는다.

## 업무별 최소 검사표

| 위험 | 실제로 확인할 것 |
|---|---|
| 타인/다른 회사 접근 | 목록·단건·이력·집계·CSV에서 값/건수 노출 여부 |
| 권한 위조 | 회사/owner/readOnly 입력 거부와 저장 값 불변 |
| 자기 승인·단계 생략 | 관리자 예외, 같은 사람 두 역할, 재무 선승인 거부 |
| 권한 변경 | 기존 토큰/기존 화면으로도 다음 요청에 역할·위임 취소 반영 |
| 경계·재제출 | 금액/시각 경계, 구버전 진행 건, 반려 후 새 규칙 |
| 동시 변경 | 같은 객체 version 충돌과 서로 다른 요청의 공유 예산 경쟁 |
| 실패 원자성 | 승인/이력 실패 시 예산·상태·이력 모두 불변, 재시도 중복 차감 없음 |
| 입력/CSV | 누락·잘못된 숫자·참조·중복·한 행 실패 시 전체 미저장 |
| 숨은 값 추측 | 비공개 필드가 검색 결과·건수·export·이력에 나타나지 않음 |

## 코드 재사용 시 주의

readOnly는 생성 입력 보호이고 읽기 비공개가 아니다. OWN은 생성자이며 담당자/부서와 같은 의미가 아니다. availableActions는 UI 정보이며 서버 검사를 대신하지 않는다. 이력은 같은 DB의 변경 기록이지 변조 방지 감사 장치가 아니다.

실제 키·토큰·비밀번호·개인 DB·업무 자료를 Git에 포함하지 않는다. 공개 데모 계정은 연습 전용이다. `.local-data/`는 Git 제외 대상이며 런처가 로컬 키를 생성한다. organization 비활성화는 조직 업무 권한을 막는 기능이지 전체 JWT/SSO 세션 폐기가 아니다.

운영 적용 전 인증/세션, 비밀값 관리, 배포, 접근 정책, 백업/복구, DB 엔진, 부하/장애와 실제 개인정보 처리를 해당 환경에서 별도 검증해야 한다. [검증 기록](VALIDATION.md)의 미검증 범위를 확인한다.
