# 고정 담당자 설정: 응시자에게 먼저 공개하지 않음

자체 제작한 연습이며 공식 숨은 요구가 아니다. 역할 진행자는 아래 정책을 고정하고 질문한 범위만 답한다. 답변에 맞춰 정책을 새로 바꾸지 않는다. 개발 방법·모범 질문·전체 정답을 먼저 알려주지 않는다. 범위 밖은 미확인으로 답한다.

## 정책

- registration_id는 하나의 등록을 식별한다. 같은 ID의 여러 행은 변경 이력이다.
- status는 confirmed / waitlisted / cancelled만 허용한다. 필수 칸 누락·잘못된 시각/상태 행은 이유와 원본 CSV 행 번호를 오류 파일에 남기고 집계에서 제외한다. 행 번호는 헤더를 1행으로 센다.
- updated_at은 오프셋이 있는 ISO 시각이며 비교는 실제 순간 기준이다. 이번 자료의 기준 시점은 2026-10-28T00:00:00+09:00이다. 기준 시점보다 나중인 행은 오류 처리한다.
- 같은 ID·같은 시각·같은 내용은 정확한 중복이므로 한 건으로 본다.
- 유효한 이력의 가장 최근 시각을 선택한다. 그 최신 시각에 서로 다른 내용이 여러 개면 해당 ID 전체를 충돌로 별도 보고하고 집계에서 제외한다. 행 순서로 결정하지 않는다. 오래된 시각의 충돌은 최신 상태가 명확하면 현재 상태 선정을 막지 않는다.
- 현재 cancelled는 확정/대기 인원과 확정률 분모에서 제외한다. 확정률은 confirmed / (confirmed + waitlisted) × 100, 소수 둘째 자리 반올림. 분모 0은 빈 값으로 표시한다.
- 결과는 cohort, confirmed, waitlisted, confirmation_rate 열의 summary.csv와 원본 행 번호/ID/이유를 담은 issues.csv, 실행 명령과 정책을 적은 README다. 충돌은 해당 최신 행들을 추적할 수 있어야 한다. 정상 이력과 단순 중복은 오류로 부풀리지 않는다.
- 결과는 로컬 파일로 재현할 수 있으면 된다. 로그인·웹 화면·DB·외부 AI·외부 전송은 필요 없다. 파일 제출만 한다.

## 고정 자료의 수작업 기대값

| cohort | confirmed | waitlisted | confirmation_rate |
|---|---|---|---|
| A | 1 | 0 | 100.00 |
| B | 1 | 1 | 50.00 |

- E01의 최신 상태는 cancelled이므로 제외한다(이전 confirmed로 세면 틀린다).
- E02는 정확한 중복이어서 확정 1명이다. E03 확정 1명, E04 대기 1명.
- E05의 최신 시각이 같고 상태가 달라 충돌 ID 1개. 원본 8·9행을 추적한다.
- E06은 원본 10행 잘못된 시각, E07은 원본 11행 허용되지 않은 상태.
- issues에는 충돌 E05와 잘못된 E06/E07이 포함돼야 한다. 중복 E02와 이전 이력 E01은 데이터 오류가 아니다.

추가 경계: 행 순서 뒤집기, 서로 다른 오프셋의 같은 순간, 분모 0, 기준 시점보다 미래, 동일 최신 시각 충돌, 열 누락. 이 중 요구에 맞는 소수를 직접 검증한다.

## 종료 후 피드백

어떤 질문으로 어떤 정책을 발견했는지, 어떤 정책을 물어보지 않고 결정했는지 대조한다. 산출물과 실행 근거가 없으면 구현·검증 통과로 기록하지 않는다. 이 파일을 읽은 뒤 같은 자료를 재응시하면 기억 효과가 있으므로 미지 과제 숙련도 측정으로 쓰지 않는다.
