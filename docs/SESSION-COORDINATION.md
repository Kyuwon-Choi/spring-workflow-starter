# 역할별 세션과 통합

단일 세션이면 기존 WORK만 사용한다. 사용자가 여러 세션 운영을 선택한 경우 아래 역할을 배분한다. 이 문서는 세션/에이전트를 자동 생성하거나 외부 메시지를 보내는 설정이 아니다. 역할을 합칠 수 있으며 실제 도구 제한을 따른다.

| 역할 | 맡는 범위 | 인계할 결과 |
|---|---|---|
| 구현/통합 | 앱 화면·API·저장·설정·의존성 연결, 전체 실행 | 실제 흐름·변경 파일·검증·현재 버전 |
| 질문/합의 | 실제 자료와 담당자 답 정리, 다음 질문/합의 초안 | 답의 출처·바뀐 조건·영향받는 요구·미확인 |
| 핵심 계산 | 합의한 계산/판정 모듈과 관련 테스트 | 입력/출력·단위·방법·불변 조건·독립 기대값·한계 |
| E2E/버그 | 실제 흐름·권한·실패 재현과 재검사 | 재현 조건·기대/실제·근거·수정 담당 |

## 공유 계약과 파일 소유

기존 WORK가 최종 상태의 정본이다. 구현/통합 세션 한 곳이 최종 반영을 맡고 나머지는 초안을 인계한다. 담당자에게는 사용자가 질문을 보내며 AI가 답을 만들지 않는다. 단일 문서를 모든 세션이 동시에 쓰게 하지 않는다.

첫 병렬 작업 전에 수정할 파일/폴더·공유 파일 소유자·입출력 형식을 적는다. 같은 파일은 한 시점에 한 세션만 수정한다. 계산 세션은 합의한 계산 파일과 테스트를, 검증 세션은 합의한 테스트와 산출물을 맡는다. 다른 역할의 제품 코드를 고칠 때에는 기존 편집을 멈추고 소유권을 넘기거나 원래 담당자가 수정한다. 변경된 파일을 확인 없이 덮어쓰지 않는다.

계산 계약에는 ID·입출력·단위·방향/시간 기준·필수 조건·오류/미완료 상태·데이터/파라미터 버전을 담는다. 같은 `score`라도 의미가 다르면 연결하지 않는다. 늦게 끝난 이전 작업의 결과가 최신 파라미터 결과를 대체하지 않게 한다. 한 작업공간의 공유 target/node_modules/DB를 여러 세션이 동시에 삭제·설치·빌드하지 않도록 실행 담당을 정한다.

## 역할별 첫 요청

```text
[구현/통합]
WORK와 실제 코드의 현재 상태를 대조하고 통합 책임을 맡아줘.
각 역할의 수정 파일과 입출력/단위 계약을 정하고 첫 실제 흐름부터 연결해줘.
다른 세션이 편집 중인 파일은 동시에 수정하지 마.
```

```text
[질문/합의]
과제 자료와 실제 담당자 답에서 결과를 바꾸는 미확인을 찾아줘.
다음 질문과 합의/변경 초안을 만들되 제품 코드는 바꾸지 마.
답을 받으면 출처·확인된 조건·영향받는 요구·미확인을 통합 세션에 인계해줘.
```

```text
[핵심 계산]
WORK의 요구와 합의한 입출력 계약으로 [지정 파일]의 계산/판정을 맡아줘.
다른 API/설정 파일은 수정하지 말고 필요한 변경을 인계해줘.
직접 계산 가능한 작은 기대값과 관련 반례로 검증하고,
fde-core-review 절차로 선택 이유·실제 검증·한계를 정리해줘.
```

```text
[E2E/버그]
확인할 코드/서버 버전과 [지정 테스트/산출물 경로]를 사용해줘.
구현에서 복사하지 않은 기대값으로 핵심 흐름·중요 실패/권한을 확인해줘.
자동 화면 조작은 실제 허용 범위 안에서만 수행해줘.
재현 입력·기대/실제·로그·관련 파일·수정 담당을 인계하고 본체는 동시에 고치지 마.
```

## 변경·중단·재접속 인계

```text
관련 요구 ID / 실제 답의 출처 / 변경된 조건:
현재 코드·데이터·파라미터 버전:
소유 파일 / 변경한 파일 / 수정 인계 여부:
입출력·단위·필수 조건 / 영향받는 API·계산·테스트:
실제 실행 명령 / 독립 기대값 / 실제 결과 / 근거 경로:
실패·미실행·남은 미확인:
마지막 저장 상태 / 실행 중인 서버·명령 / 다음 담당과 작은 작업:
```

첫 흐름 통합, 중요한 요구 변경, 핵심 계산 통합, 최종 검증 때 동기화한다. 매 도구 호출마다 모든 문서를 다시 읽거나 모든 테스트를 반복하지 않는다. 세션이 끊기면 실제 파일·WORK·실행 프로세스를 대조하고 중복 실행/오래된 에디터 저장을 피한다. 기록에 없는 작업을 완료로 추정하지 않는다.

`fde-core-review`는 설명 근거, [계산 검증 예제](../recipes/core-validation/README.md)는 작은 독립 정답, [검증 기록 대조](EVIDENCE.md)는 요구별 근거와 현재 파일 버전 확인에 사용한다. 서로 다른 역할의 동의만으로 테스트 통과나 담당자 수용으로 표시하지 않는다.
