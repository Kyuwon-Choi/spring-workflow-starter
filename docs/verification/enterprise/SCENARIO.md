# 엔터프라이즈 변경 검증의 고정 기준

2026-10-28. 사용자 요청에 따른 자체 가상 정책이다. 실제 대회 출제/현업 답변이 아니며 구현 후 편의에 따라 요구를 삭제하지 않는다.

1. 인증 계정은 한 회사에 속한다. 서버 DB의 활성 소속·역할·프로젝트 관계를 실행 시점에 조회한다. 회사/부서/소유자는 클라이언트가 지정하지 못한다.
2. 요청은 생성 당시 프로젝트 소유 부서와 회사에 고정된다. 생성은 현재 참여 프로젝트에서만 가능하다. 부서 이동은 과거 요청의 부서를 바꾸지 않는다.
3. 직원은 현재 참여 프로젝트의 자기 요청만, 부서장은 현재 자기 부서의 참여 프로젝트 요청을, 재무 담당자는 참여 프로젝트 요청을 조회한다. 회사 관리자 역할만으로 업무 조회·승인을 허용하지 않는다.
4. 조회 범위는 상세·목록·페이지/총건수·집계·CSV·이력·검색에 일치한다. 내부 검토 메모는 부서장/재무/유효 위임자만 보며 직원에게는 상세/이력/CSV/검색에서 숨긴다.
5. 제출은 생성자만 한다. 승인자는 신청자와 달라야 하며, 관리자도 자기 신청을 승인하지 못한다. 재무 2차 승인자는 부서 승인자와도 달라야 한다.
6. V1은 부서 승인으로 종료한다. V2는 금액 300000 초과일 때 부서 승인 후 재무 승인이 필요하다. 300000은 부서 승인으로 종료한다.
7. 승인 규칙은 변경 불가 버전으로 저장하고, 제출 시 서버 시각 기준 유효한 버전을 선택해 요청에 고정한다. 시행 시각 정각부터 새 버전을 적용한다. 기존 제출/승인 건은 고정된 버전을 유지한다.
8. 반려 후 본인 재제출은 현재 규칙을 새로 선택하고 이전 심사 메모/승인자/반려 사유를 초기화한다. 이전 이력은 보존한다. 완료 건은 재처리하지 않는다.
9. 부서장은 자기 부서·프로젝트의 부서 승인 권한을 같은 회사의 참여자에게 기간 한정 위임한다. 시작 포함/종료 제외다. 자기 자신에게 위임하거나 재위임하지 못한다. 위임자는 언제든 취소할 수 있다.
10. 위임은 실행 때 위임자/수임자의 현재 소속·역할·프로젝트와 유효 기간을 재확인한다. 신청자 자신 또는 신청자인 위임자를 대신한 승인은 금지한다.
11. 모든 회사 내 변경은 회사의 공통 잠금을 먼저 획득한다. 취소/소속 변경이 먼저 완료되면 이후 승인은 거부한다. 승인이 먼저 완료된 경우 소급 취소하지 않고 이력에 남긴다.
12. 프로젝트 예산은 여러 요청이 공유한다. 최종 승인 시 요청 금액만 원자적으로 차감하며 초과/중복 차감을 금지한다. 승인 또는 이력 저장 실패 시 예산·요청·이력 전부 롤백한다.
13. 설정 변경도 같은 회사 범위와 현재 역할을 확인하고, 변경 전후·행위자·시각을 기록한다. 기존 규칙 버전은 수정하지 못한다. 소속 변경은 expectedVersion으로 충돌을 검사한다.
14. 기존 support/procurement/inventory/training 테스트와 실행 계약을 유지한다. enterprise 기능은 정의의 정책 ID로 선택하며 공통 엔진에 회사나 업무 도메인 이름을 하드코딩하지 않는다.
15. 제공 가능한 소스·실행 문서·자동 검사·실제 HTTP·브라우저·재기동 보존 근거를 남긴다. SSO·다중 회사 동시 소속·조직 트리 임의 깊이·외부 시스템 원자성·운영 규모 성능은 이 범위 밖이다.

순차 검증: V1 요청 제출→V2 게시→구버전 처리/신규 고액 2차 승인→반려 재제출→위임 취소/기간 경계→서로 다른 신청의 예산 동시 경쟁. 시행 시각·예산·사용자는 검사별 고정 입력으로 정한다.
