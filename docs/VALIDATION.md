## 자신의 환경에서 재현

[빠른 시작](QUICKSTART.md)에 따라 의존성을 준비하고, 실행 중인 해당 서버를 종료한 상태에서 빌드한다.

```bash
./scripts/check.sh
./npmw run vitest-run -- --coverage.enabled=false
./mvnw -ntp -Dskip.installnodenpm -Dskip.npm verify
```

프론트가 JAR에 들어가려면 먼저 Vite 빌드가 있어야 한다. check.sh는 Vite 빌드를 포함한다. 각 명령을 이미 통과했다면 새 변경/실패 근거 없이 반복할 필요는 없다.

기본 8080 서버 실행 후 별도 터미널:

```bash
python3 scripts/fde-smoke.py
```

이 스크립트는 합성 데이터를 추가한다. 조직 59요청을 실행한 로컬 검증기/원본 로그는 개발 작업 공간에 보존했으며, 공개 묶음에는 개인 경로와 서버 로그를 제외한 결과 요약을 넣었다. [조직 업무 가이드](ENTERPRISE-GUIDE.md)에서 같은 역할별 흐름을 직접 재현할 수 있다.

## 이전 단계와 별도 경로

최초 공통 키트는 213개 백엔드/188개 프론트였고, 교육 과제에서 서버 전용 필드와 OWNER_ONLY를 보완한 뒤 조직 확장을 추가했다. 이 숫자들을 현재 전체 수치와 합산하지 않는다. training은 테스트 전용이며 원본 앱에서 별도 생산용 메뉴로 등록하지 않는다.

DuckDB 1.4.1 분석 recipe는 4개 검사와 실제 CSV/JSON 출력을 확인했다. Timefold 공식 Spring 예제는 고정 커밋 76993a35123a127f9b630a8f7a37a1fbe76a24b0에서 7개 실행 통과/3개 조건부 skip이며 실제 solver REST 검사가 포함된다. 다시 받은 소스/라이선스 30파일 일치를 확인했다. 나머지 카드는 소스 확인 B 또는 보류 C이며 설치·기동 통과로 올려 적지 않는다.

## 남은 검증

사용자 직접 블라인드 리허설/시간 측정·사후 설명, 공식 평가 JDK/네트워크/미리보기/반입 허용, 새 기기의 캐시 없는 설치는 남아 있다. 확인한 브라우저 흐름이 모든 UI 조합·Cypress 전체 검증을 뜻하지 않는다.

조직 검증은 한 계정 한 회사·평면 부서·프로젝트·로컬 H2 범위다. SSO/전체 JWT 폐기·임의 조직 트리·다중 회사·운영 DB·부하/장애·외부 시스템 원자성·모델/OCR·전체 시스템 보안 인증은 검증하지 않았다. 관계 검사는 서비스 경계이며 도메인별 DB foreign key는 아니다. 정의/상태 자체 변경에는 별도 데이터 migration이 필요하다.

## 2026-10-30 미리보기 실행기

[preview.sh](../scripts/preview.sh)는 빌드된 JAR를 0.0.0.0과 지정 포트로 foreground 실행한다. 기본 로컬 데모의 루프백 설정은 유지한다. 로컬 임시 서버에서 wildcard 리스너·로그의 실제 포트·/fde HTTP 200·인증 후 catalog를 확인했고 잘못된 포트 입력을 거부했다. 검증 뒤 임시 서버를 종료했다. [실제 결과](verification/preview-validation.json)를 본다.

이 검사는 공식 Cofa 포트 전달/미리보기 연결이나 사용자 화면 버튼 조작의 완료를 의미하지 않는다. [제공 환경 실행 절차](PREVIEW.md)에 따라 현장에서 확인해야 한다. 애플리케이션 코드를 바꾸지 않아 전체 241/191 검사를 반복하지 않았다.
