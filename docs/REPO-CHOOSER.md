# 문제별 오픈소스 선택

과제의 핵심 산출물과 제공 코드를 먼저 확인한다. 기존 저장소가 있으면 그 계약·스택을 유지하고 아래 모듈을 필요한 만큼만 쓴다. 상세 고정 커밋·라이선스·시작 위치는 [20개 선택 카드](REPO-CATALOG.md)에 있다.

| 문제에서 보이는 신호 | 먼저 확인할 질문 | 첫 선택 | 처음 확인할 결과 |
|---|---|---|---|
| 신청/승인/처리 상태 | 누가 어떤 범위를 보고 어떤 동작을 하나? | 선택형 workflow/enterprise 모듈 | 한 건 입력→권한→동작→이력 |
| CSV 여러 파일/갱신 이력/집계 | 키·최신·동률·분모·오류 처리 기준은? | DuckDB/Commons CSV | 고정 원본 행과 기대 집계 |
| XLSX 여러 시트·수식/보고서 | 수식 원문인가 계산 값인가? 어느 시트/열인가? | Apache POI | 파일 읽기→수식/셀 값→요구 파일 |
| PDF 조항/페이지 근거 | 텍스트 PDF인가? 페이지/원문이 결과에 필요한가? | PDFBox; 다중 형식은 Tika | 페이지별 추출과 원본 대조 |
| 스캔 문서/이미지 글자 | 언어·회전·품질·인식 실패 기준은? | Tesseract 조건부 | 실행기/언어 데이터→한 페이지 인식 |
| 품목/설비명 표기가 제각각 | 자동 확정 기준과 동점/모호함은? | RapidFuzz | 정규화·후보/점수·검토 대상 |
| 공정 선후관계/경로/순환 | 방향·가중치·도달 불가를 어떻게 처리하나? | NetworkX; 표시는 React Flow | 경로/순환/위상 순서 |
| 인원/설비/시간 배정 | 반드시 지킬 제약과 선호 목표는? | Timefold | 제약 준수와 불가능 사례 |
| KPI 추이·분포·비교 화면 | 계산 단위·기간·결측·필터 기준은? | ECharts; Python 화면은 Streamlit | 독립 기대 집계→차트 표시 |
| 큰 표/관리 폼 | 서버 페이지/정렬/권한 계약은? | TanStack/Refine | 현재 API와 연결한 목록/폼 |
| 중첩 JSON·외부/AI 응답 | 허용 필드/타입/누락·의미 오류는? | networknt JSON Schema | 정상·누락·type·추가 필드 거부 |
| 외부 API 자주 실패 | timeout·재시도 가능 오류·멱등성은? | 기존 HTTP timeout + Resilience4j | 제한된 재시도·실패 표시 |
| 실제 AI/RAG 요구 | 제공된 모델/API·근거·오류 정책은? | Spring AI 후보 | 실제 허용 호출과 오류/근거 |

## 확인 수준과 선택 비용

추가 8개 중 POI/PDFBox/RapidFuzz/NetworkX는 독립 패키지의 작은 입력→결과를 실행했다. 앱 통합·실제 제공 데이터·공식 환경 검증은 아니다. ECharts/JSON Schema/Resilience4j/Tesseract는 소스 확인 후보다. 설치/기동을 통과한 것으로 표시하지 않는다.

- Java 파일 모듈: POI/PDFBox의 검증한 배포 버전부터 작은 파일 처리에 연결한다.
- Python 계산: 이미 Python 경로가 적합할 때 RapidFuzz/NetworkX를 선택한다. 단순 계산 때문에 별도 웹 서버를 추가하지 않는다.
- JSON Schema: Jackson 2/3 계열을 맞춘다. 스키마 검사는 업무 정답·권한을 대신하지 않는다.
- 장애 처리: 클라이언트 timeout과 멱등성이 먼저다. 승인/결제의 무조건 재시도를 만들지 않는다.
- OCR: 실행 파일과 언어 데이터 확인이 먼저다. 없으면 설치·처리 비용을 판단하고 미완료를 표시한다.

필수 요구를 현재 기반과 작은 확장으로 충족할 수 있으면 그대로 사용한다. 새 도구는 필요한 기능의 최소 입력→결과를 확인한 뒤 선택하고 출처·버전·변경·실행 범위를 WORK에 기록한다. 과제 자료를 임의 외부 서비스로 보내지 않는다.
