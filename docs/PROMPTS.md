# 단계별 프롬프트 카드

실제 과제·규칙·남은 시간에 맞게 채운다. 모든 카드를 매번 실행할 필요는 없다. 실행하지 않은 검증을 통과로 기록하지 않는다.

질문·계획 반복 작업은 [fde-discovery / fde-planning](../skills/README.md)로 준비했다. 아래 카드는 간단한 수동 사용용이며 실제 시험의 자료·AI 사용 제한을 우선한다.

담당자 질문과 구현 AI 지시는 상대가 다르다. 업무 담당자에게는 실제 사례·규칙·예외를 묻고, 구현 AI에게는 확인된 조건을 근거로 계획·구현·검증을 맡긴다. [인터뷰·계획 절차](WORKFLOW.md)의 질문 구성과 계획 요청을 함께 본다.

## 1. 시작·범위 결정

```text
남은 시간은 [분], 구현 종료 목표는 [시각]이다.
README, 관련 코드·테스트, 데이터, 실행 안내를 확인해라.
우선 목표·사용자·필수 산출물·제약을 정리하고,
명시된 사실 / 불명확한 점 / 임시 가정을 구분해라.
기존 과제의 API와 스택을 우선하라.
명시된 필수 요구 각각의 완료 조건과 검증 방법,
가장 중요한 사용자 흐름 하나를 먼저 완성하는 계획을 제안해라.
담당자에게 필요한 질문과 내가 결정해야 할 선택지를 짧게 정리해라.
문제·병목·원본·성공 사례·범위/제외·제약을 묶어 합의안을 작성하되,
실제 담당자 답 없이 합의 완료로 표시하지 마라.
WORK.md에 STATE·근거·다음 전환 조건과 실제 남은 시간을 남겨라.
```

## 2. 기능 한 단위 구현

```text
이번 작업 목표: [사용자 행동과 관찰 가능한 결과]
관련 범위: [파일·기능]
유지할 계약: [입출력·정책·기존 동작]
완료 조건: [구체적인 항목]
검증: [입력·예상값·명령 또는 화면 동작]
우선 이 흐름을 끝까지 연결하고 실제로 실행해라.
중대한 불명확성은 짚고, 독립적으로 가능한 부분을 진행해라.
변경·실행 결과·남은 문제를 구분해 보고해라.
첫 흐름이 실행되면 담당자에게 보여줄 실제 입력·결과·한계·확인 질문을 정리해라.
답변 대기 중에는 답과 독립적인 승인된 작업을 이어가라.
```

## 3. 오류 수정

```text
관찰한 현상: [실제 출력]
기대 결과: [요구와 근거]
재현 조건: [입력·명령·환경]
원인 가설을 실제 코드·로그와 대조하고 최소 수정해라.
수정 후 같은 재현 절차와 관련 회귀 검증을 실행해라.
실패가 재현되지 않으면 원인을 확정했다고 쓰지 마라.
```

## 4. 제출 후보 검토

```text
WORK.md의 요구와 실제 제출 후보를 대조해라.
필수 기능 누락, 실제 실행 오류, 잘못된 계산·입력 처리,
외부 연동 실패, 문서와 코드 불일치를 우선 확인해라.
지적마다 파일·위치·발생 조건·확인 방법을 붙여라.
이미 확인한 문제와 아직 검증이 필요한 가설을 구분해라.
남은 시간 안에 필수로 수정할 항목을 우선순위로 제시해라.
```

## 5. 세션 인수인계

```text
실제 파일과 실행 결과를 바탕으로 WORK.md를 갱신해라.
목표·제약·결정 이유·현재 상태·검증 근거·남은 오류·다음 작업을 남겨라.
다음 세션이 읽을 파일과 실행 명령을 적어라.
실행하지 않은 것은 미검증으로 표시해라.
```

## 6. 중간 확인·수용 요청 준비

```text
WORK.md와 실제 실행 결과를 바탕으로 담당자에게 보낼 문장을 만들어라.
확인할 요구 ID·실제 입력·관찰한 결과·아직 안 되는 것·업무 판단 질문을 담아라.
현재값·개선율·담당자 답변을 만들지 마라.
내가 실제 답을 붙이면 확인된 범위와 수정 요구·예상값·시간을 갱신해라.
자체 검사 통과와 담당자 수용을 별도로 기록해라.
```

## 7. 읽기 전용 교차검토

기본은 단일 세션 검토다. 사용자가 별도 세션 검토를 지시했고 실제 환경이 허용할 때에만 다른 세션에 아래를 전달한다. 이 카드만으로 새 에이전트/세션을 자동 생성하지 않는다.

```text
읽기 전용으로 [과제 자료 경로], [WORK.md 경로], [검토 범위]를 대조해라.
합의 단계라면 누락·모순·근거 없는 가정을,
구현 단계라면 실제 오류·계산·권한·상태 변경·중복·실패 처리를 우선 찾아라.
지적마다 요구 ID·파일/위치·발생 조건·확인 방법을 붙이고
확인한 결함과 아직 검증이 필요한 가설을 구분해라.
파일 수정·외부 전송·상태 변경 명령은 실행하지 말고
남은 시간 안에 확인할 중요한 항목부터 제시해라.
```

검토 결과의 동의/칭찬은 실행 증거가 아니다. 발견된 문제는 메인 작업에서 재현·수정·관련 재검증 후 기록한다.
