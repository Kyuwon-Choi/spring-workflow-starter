# 단계별 프롬프트 카드

실제 과제·규칙·남은 시간에 맞게 채운다. 모든 카드를 매번 실행할 필요는 없다. 실행하지 않은 검증을 통과로 기록하지 않는다.

질문·계획 반복 작업은 [fde-discovery / fde-planning](../skills/README.md)로 준비했다. 아래 카드는 간단한 수동 사용용이며 실제 시험의 자료·AI 사용 제한을 우선한다.

담당자 질문과 구현 AI 지시는 상대가 다르다. 업무 담당자에게는 실제 사례·규칙·예외를 묻고, 구현 AI에게는 확인된 조건을 근거로 계획·구현·검증을 맡긴다. [인터뷰·계획 연습](WORKFLOW.md)의 질문 구성과 계획 요청을 함께 본다.

## 1. 시작·범위 결정

```text
남은 시간은 [분], 구현 종료 목표는 [시각]이다.
README, 관련 코드·테스트, 데이터, 실행 안내를 확인해라.
우선 목표·사용자·필수 산출물·제약을 정리하고,
명시된 사실 / 불명확한 점 / 임시 가정을 구분해라.
기존 과제의 API와 스택을 우선하라.
완료 조건 3~5개와 각각의 검증 방법,
핵심 사용자 흐름 하나를 먼저 완성하는 계획을 제안해라.
담당자에게 필요한 질문과 내가 결정해야 할 선택지를 짧게 정리해라.
```

## 2. 기능 한 단위 구현

```text
이번 작업 목표: [사용자 행동과 관찰 가능한 결과]
관련 범위: [파일·기능]
유지할 계약: [입출력·정책·기존 동작]
완료 조건: [구체적인 항목]
검증: [입력·예상값·명령 또는 화면 동작]
우선 이 흐름을 끝까지 연결하고 실제로 실행해라.
중대한 불명확성은 짚고, 독립적으로 가능한 부분을 진행해라.
변경·실행 결과·남은 문제를 구분해 보고해라.
```

## 3. 오류 수정

```text
관찰한 현상: [실제 출력]
기대 결과: [요구와 근거]
재현 조건: [입력·명령·환경]
원인 가설을 실제 코드·로그와 대조하고 최소 수정해라.
수정 후 같은 재현 절차와 관련 회귀 검증을 실행해라.
실패가 재현되지 않으면 원인을 확정했다고 쓰지 마라.
```

## 4. 제출 후보 검토

```text
WORK.md의 요구와 실제 제출 후보를 대조해라.
필수 기능 누락, 실제 실행 오류, 잘못된 계산·입력 처리,
외부 연동 실패, 문서와 코드 불일치를 우선 확인해라.
지적마다 파일·위치·발생 조건·확인 방법을 붙여라.
이미 확인한 문제와 아직 검증이 필요한 가설을 구분해라.
남은 시간 안에 필수로 수정할 항목을 우선순위로 제시해라.
```

## 5. 세션 인수인계

```text
실제 파일과 실행 결과를 바탕으로 WORK.md를 갱신해라.
목표·제약·결정 이유·현재 상태·검증 근거·남은 오류·다음 작업을 남겨라.
다음 세션이 읽을 파일과 실행 명령을 적어라.
실행하지 않은 것은 미검증으로 표시해라.
```

## 6. 설명 연습 전용

```text
내 산출물에서 구조 선택·데이터 흐름·실패 가능성·검증 범위를 묻는
질문 5개를 내라. 답과 해설은 먼저 보여주지 마라.
내가 AI 없이 답한 다음 실제 코드·기록과 비교해 피드백해라.
```

사후 질문에서 AI 사용이 제한되면 해당 단계에는 이 카드를 사용하지 않는다.
