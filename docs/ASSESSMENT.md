# 평가 환경에 준비물을 적용하는 순서

이 저장소는 사전 작성한 개인 준비물이다. 공개 GitHub에 있다는 사실만으로 특정 시험에서 사용이 허용되지는 않는다. 플랫폼의 최신 공식 안내가 우선한다. 실제 시험 문제·데이터·결과물을 외부 저장소/서비스로 전송하지 않는다.

## 과제 시작 전

1. 사전 코드·공개 자료·개인 문서·Skills·외부 검색의 허용 범위를 각각 확인한다. 개인 PC 경로가 제공 환경에 있다고 가정하지 않는다.
2. 제공 코드/언어/실행 방법/포트/제출 형식/작업 타이머/후속 절차를 읽는다.
3. 기존 저장소 과제면 제공 코드부터 실행한다. 신규 구현이고 반입이 허용될 때에만 이 키트를 가져온다.
4. 공개 코드 취득은 제공 환경 안의 허용 경로를 사용한다. 감독/보안/도구 제한을 우회하지 않는다.

## 미리보기 실행

제공 안내에서 요구하면 [PREVIEW](PREVIEW.md)에 따라 0.0.0.0으로 실행하고, 로그에서 확인한 실제 포트와 /fde 경로를 입력한다. 서버 터미널을 유지한 채 화면 동작을 직접 확인한다. 플랫폼의 실제 연결은 로컬 HTTP 검사와 구분한다.

## 작업 시작 후

[WORKFLOW](WORKFLOW.md)와 [WORK 템플릿](templates/WORK.md)에 따라 자료→실제 담당자 답→요구/완료 조건→계획→구현→검증을 연결한다. 모든 기능을 보여주기보다 필수 결과를 먼저 만든다. 설치가 막히면 제공 환경과의 적합성을 재판단한다.

사용한 코드의 출처·고정 버전·재사용 범위·변경 이유를 남긴다. 기능 없는 버튼·샘플 응답으로 실제 연동을 완료 처리하지 않는다. 사전 도구가 과제의 결과물 전체를 대체하는 방식은 허용 여부를 별도로 확인한다.

## 제출과 후속 답변

실제 타이머에서 제출/검증/후속 단계 시간을 먼저 확보한다. 제출 전 실행·파일 저장·결과·미완료를 확인하고, 제출 확정 뒤 변경 가능 여부는 플랫폼 안내를 따른다. AI 사용 금지 문항에서는 이 키트의 skill이나 다른 AI를 사용하지 않고 직접 답한다.

개인 연습에서 수행한 로컬 브라우저 검증은 평가에서 Computer Use가 허용된다는 뜻이 아니다. 시험 중에는 실제 허용된 기능만 사용한다.
