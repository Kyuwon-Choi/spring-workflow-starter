# 담당자 질문부터 결과 설명까지

목표는 프롬프트 문장을 꾸미는 것이 아니라 **확인된 요구를 구현·검증과 연결하는 것**이다. [WORK 템플릿](templates/WORK.md)을 새 작업 기록으로 복사하고 원문/답변/가정을 구분한다. 실제 평가에서는 해당 자료와 AI 사용이 허용되는지 먼저 확인한다.

## 1. 자료를 읽고 다음 질문 고르기

사용자, 현재 입력, 해결할 병목, 결과물 형식, 기존 코드와 제한을 먼저 읽는다. 이미 문서에 있는 내용을 다시 묻지 않는다. 모르는 조건 중 구현이나 정답이 달라지는 것을 우선한다.

```text
과제와 자료: [실제 원문/경로]
이미 확인한 사실과 출처: [내용]
담당자에게 실제로 받은 답: [내용 또는 없음]
남은 시간/허용 도구: [값]

확정 사실·가정·미확인을 나누고 다음 질문을 최대 3개 골라줘.
질문은 담당자에게 복사할 문장으로 쓰고,
각 답이 계산·권한·흐름·출력 중 무엇을 바꾸는지 알려줘.
담당자의 답을 대신 만들지 마.
```

질문 예: “동일 신청번호의 내용이 다르면 갱신인가요, 충돌인가요?”, “부서장이 자기 신청도 승인할 수 있나요?”, “30만원 **초과**와 **이상** 중 어느 기준인가요?”, “부서 이동 뒤 기존 신청을 누가 보나요?”처럼 구체 사례를 쓴다. 실제 답을 기록하기 전 예시를 확정 요구로 넣지 않는다.

## 2. 요구·완료 조건 만들기

| ID | 근거 | 확정 요구 | 완료 조건 | 검증 입력/예상값 |
|---|---|---|---|---|
| R1 | 담당자 답 A | 30만원 초과는 재무 승인 | 300000은 부서 완료, 300001은 재무 대기 | 두 경계값의 상태 |
| R2 | 담당자 답 B | 본인 승인 금지 | 관리자도 본인 건 거부, 값/이력 불변 | 같은 사람/다른 사람 |

위 표는 연습 예시다. 실제 과제에서 받은 답으로 대체한다. 정상 사례, 중요한 예외·권한, 제출 형식을 설명할 수 있으면 첫 흐름 계획을 시작하고 남은 질문은 관련 작업 전에 이어간다.

## 3. 계획과 기반 선택

기존 코드가 있으면 그것을 먼저 실행한다. 신규 업무 상태 관리이면 이 키트를, 파일 정답/집계이면 [분석 recipe](../recipes/analytics/README.md)를, 배정/문서/AI 등이 핵심이면 [레포 카드](REPO-CATALOG.md)를 비교한다.

```text
확정 요구와 완료 조건: [ID/출처/기대값]
미확인 정책: [항목과 영향]
기존 코드/허용 키트/입출력 경로: [실제 경로]
남은 구현 시간과 제출 마감: [값]

각 요구를 그대로 사용/정의 변경/확장 구현/다른 기반으로 판단해줘.
첫 입력→실제 결과를 가장 먼저 연결하는 계획을 세우고,
작업별 요구 ID·수정 위치·완료 조건·검증 방법을 붙여줘.
검증·오류 수정·제출 여유를 포함하고 미확인 정책을 임의 확정하지 마.
```

사람이 확인할 것은 요구 누락, 첫 실행이 늦어지는 구조, 근거 없는 정책 결정이다. 기간 위임/회사 격리를 단순 OWN으로 처리하거나 분석 문제에 불필요한 웹앱을 만들지 않는다.

## 4. 작게 구현하고 실제 실행

```text
이번 목표: [한 흐름/요구 ID]
유지할 계약: [API·기존 동작·권한·데이터]
허용 변경: [파일/확장 경계]
검증: [입력→예상 결과, 실패 시 불변 조건]

계획대로 이 범위를 구현하고 실제 실행해줘.
정의/확장으로 해결할 수 있는데 공통 엔진을 수정하지 마.
실행 결과·실패·미검증을 구분하고 선택 이유를 기록해줘.
```

입력→저장→동작→결과 한 건을 먼저 완성한다. 중간 요구 변경은 [변경 대응](CHANGE-CONTROL.md) 절차를 사용한다. 코드가 나왔다는 이유로 정상/권한/실패 검증을 생략하지 않는다.

## 5. 검증·정리·직접 설명

완료 조건별 실제 결과를 WORK에 기록한다. 다른 계정 접근, 금지 상태, 경계값, 오래된 version, 실패 시 데이터/예산/이력 불변을 필요한 범위에서 검사한다. 테스트 수만으로 모든 요구 충족을 판단하지 않는다.

제출 전에는 실행 명령, 핵심 파일, 선택 이유, 재사용/직접 구현 범위, 실제 검사, 남은 한계를 정리한다. AI 없이 “왜 이 질문을 했는지→어디에 구현했는지→무엇으로 확인했는지”를 설명한다. [프롬프트 카드](PROMPTS.md)와 [선택형 skill](../skills/README.md)은 이 절차를 돕는 자료다.
