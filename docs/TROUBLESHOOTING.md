# 실행 문제 해결

먼저 실행한 명령·오류 마지막 부분·포트·현재 경로·Java 버전을 기록한다. 토큰/키/실제 사용자 자료는 로그에 붙이지 않는다. 강제 종료·DB 삭제로 원인을 덮지 않는다.

| 증상 | 확인과 조치 |
|---|---|
| 8080/8082 접속 안 됨 | 서버 준비 메시지와 프로세스 확인. 기본은 8080, 조직은 8082. 시작 실패 로그를 읽는다 |
| 포트 사용 중 | 해당 포트의 프로세스가 이 프로젝트인지 확인하고 원래 터미널에서 종료. 다른 앱을 임의 종료하지 않는다 |
| Permission denied | 실행 파일의 실행 권한과 사용 셸 확인. ZIP 도구가 권한을 잃었다면 해당 wrapper/scripts의 실행 비트를 복원 |
| Java 버전/컴파일 오류 | `java -version`, `./mvnw -v`. Java 21+와 실제 선택된 JDK 확인 |
| 첫 다운로드 실패 | 네트워크/프록시/레지스트리 접근과 오류 확인. 의존성 버전을 무작정 최신으로 바꾸지 않는다 |
| JAR not found | 프론트 빌드 후 Maven verify로 JAR 생성. scripts/check.sh만으로 JAR가 생성된다고 가정하지 않는다 |
| 화면 변경이 안 보임 | 내장 화면은 프론트 재빌드 필요, JAR는 Maven 재빌드·재시작 필요. 브라우저 새로고침만으로 소스가 반영되지 않음 |
| JSON을 바꿨는데 메뉴가 같음 | 올바른 main 리소스에 복사했는지와 서버/JAR 재빌드 여부 확인. 정의는 시작 때 읽음 |
| Invalid trusted FDE definition | ID/상태/필수 속성/참조/필드 수/readOnly required 조합을 [계약](DOMAIN-REFERENCE.md)과 비교 |
| Unknown type policy/action extension | 등록된 Spring bean id와 JSON policy/extension 확인. 조직 어댑터의 필드/상태 계약도 비교 |
| 로그인 401 | 데모별 계정/포트와 로그인 응답 확인. 키/토큰 만료·다른 서버 키 여부 확인 후 다시 로그인 |
| enterprise 메뉴 없음 | enterprise-demo.sh 실행 여부, 로그인 계정의 현재 조직 소속/활성화 확인. 기본 8080은 소속을 자동 만들지 않음 |
| training/events 메뉴 없음 | 테스트 전용 정의다. 기본 서비스에 자동 노출하지 않음 |
| 부서장은 보이지만 승인 버튼 없음 | 프로젝트·부서·현재 상태·자기 신청·위임 유효성 확인. ORG_ADMIN만으로 승인 권한을 주지 않음 |
| 403 또는 404 | 권한·현재 소속·프로젝트·범위를 확인. 접근 불가를 404로 처리할 수 있음 |
| 409 | 오래된 version이면 재조회. 상태·고유 키·예산 부족이면 조건을 수정. 무조건 자동 재시도하지 않음 |
| CSV import 거부 | preview 오류 row/detail, readOnly 열·참조 ID·100행/100000자 한도 확인. import는 다시 검증함 |
| H2 file locked | 같은 파일 DB를 쓰는 다른 서버가 있는지 확인. 다른 터미널의 실행을 정상 종료하고 재시도 |
| Liquibase checksum 오류 | 기존 changeSet 수정 여부 확인. 변경을 복구하고 새 changeSet으로 작성. 검증을 끄거나 DB를 지우지 않음 |
| Vite 9000이 다른 데이터 표시 | 기본 프록시는 8080이다. 8082 조직 데모와 별도 DB인 점 확인 |

macOS에서 현재 포트 확인:

```bash
lsof -nP -iTCP:8080 -sTCP:LISTEN
lsof -nP -iTCP:8082 -sTCP:LISTEN
```

제공 평가 환경에서 막히면 실제 허용된 포트/JDK/미리보기 경로를 확인한다. 플랫폼 관리·감독·보안 설정을 변경하지 않는다. 설치가 오래 막히면 원인과 제공 코드/단순 경로의 비용을 비교한다. 필요한 외부 연동을 가짜 응답으로 바꾸고 완료 처리하지 않는다.
